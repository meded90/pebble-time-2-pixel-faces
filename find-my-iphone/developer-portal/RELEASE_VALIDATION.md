# Release validation: Find My iPhone 0.1.4

Дата проверки: 2026-09-01

## Подтверждено

- целевая платформа: Pebble Time 2 (`emery`);
- нативное приложение собирается Pebble SDK без ошибок;
- PBW устанавливается и запускается в эмуляторе Emery;
- стартовый экран `AUTH_REQUIRED` визуально проверен в эмуляторе;
- удержание Select защищено таймером 650 мс;
- AppMessage ACK ограничен тайм-аутом 3 секунды;
- HTTPS-запросы ограничены тайм-аутом 20 секунд;
- повторные команды защищены `REQUEST_ID`, флагом одного запроса в полёте и cooldown 10 секунд;
- выбор нескольких iPhone работает через Up/Down;
- Back в состоянии `ERROR` возвращает приложение в `READY`, в остальных состояниях закрывает его;
- экран успеха возвращается в `READY` через 4 секунды;
- поддерживаются системные языки EN, RU, UK, DE, ES, FR, IT и PT, остальные используют EN;
- пароль и код 2FA очищаются после отправки и не сохраняются;
- сессия Apple, cookies и выбранный ID устройства сохраняются локально в Pebble Core на iPhone;
- production-зависимости прошли `npm audit`: известных уязвимостей нет;
- PBW и все обязательные изображения соответствуют подготовленным размерам RePebble;
- foreground подушки и телефона генерируется ровно 145×99 под нативный `BitmapLayer`, поэтому на Emery уменьшается целиком и не обрезается;
- текущий PBW установлен и запущен в стандартном SDK-эмуляторе Emery после тайм-аута BlobDB в браузерном QEMU;
- экран `AUTH_REQUIRED` текущей сборки проверен по снимку SDK-эмулятора: диван, подушка, телефон и CTA полностью помещаются в экран 200×228;
- автотест моделирует закрытие WebView, перезапуск PebbleKit JS и ручное повторное открытие на сохранённых шагах выбора устройства и готового подключения;
- автотест Apple SRP проверяет перенос обновлённых `scnt`, `X-Apple-ID-Session-Id`, auth-атрибутов и cookies между запросами, переход ответа 409 в шаг 2FA и отсутствие пароля в сохранённом состоянии;
- автотест воспроизводит подтверждённый на физическом iPhone ответ HTTP 202 после доставки trusted-device кода и проверяет переход к шагу ввода 2FA вместо возврата к паролю;
- автотесты `npm test`, проверка каталога `npm run projects:check` и синтаксическая проверка PebbleKit JS прошли;
- RePebble принял PBW как `Find My iPhone 0.1.4` для `emery`; dashboard и публичный API показывают релиз опубликованным и текущим;
- скачанный из публичного API PBW 0.1.4 совпал с локальной опубликованной копией по SHA-256 и содержит обработку успешных статусов HTTP 200, 202 и 204;
- production-описание без тестовой пометки сохранено в dashboard; публичная карточка может обновить закэшированный текст с задержкой.

## Не проверено на реальном устройстве

- полное завершение входа после ввода trusted-device кода; принятие пароля, доставка кода и ответ Apple HTTP 202 подтверждены пользователем на физическом iPhone;
- фактический звук на физическом iPhone после команды `playSound`;
- работа в связке физический Pebble Time 2 + Pebble Core на iPhone;
- установка текущего PBW в браузерный QEMU: загрузка завершилась тайм-аутом ожидания ответа BlobDB;
- отправка формы входа в QEMU с реальными учётными данными: она намеренно не выполнялась, поскольку публичный QEMU может направлять заблокированные запросы через внешний CORS-прокси.
