# Как внести изменения

[English](CONTRIBUTING.md) · **Русский**

Спасибо за улучшение проектов Pebble Time 2. По возможности ограничивайте одно
изменение одним циферблатом, приложением или общей задачей репозитория.

## Настройка окружения

```bash
brew install node libpng uv
uv tool install pebble-tool
pebble sdk install latest
```

`make build` собирает все циферблаты, `make standard-apps` — приложения на
публичном SDK. Voice Drop входит в `make patched-apps`, потому что текущим
исходникам нужен пропатченный PebbleOS SDK из
[`voice-drop/README.ru.md`](voice-drop/README.ru.md).

## Добавление или обновление Pebble-проекта

1. Храните каждый проект в отдельном каталоге со своими `package.json`, UUID,
   версией, исходниками, ресурсами и результатом сборки.
2. Никогда не меняйте UUID уже опубликованного приложения: RePebble воспримет
   новый UUID как другое приложение.
3. Используйте `README.md` как основной английский документ, а `README.ru.md` —
   как дополнительный русский. Команды, требования, приватность и границы
   проверки должны совпадать по смыслу.
4. Добавьте нативное превью: строго 200×228 для Emery и 260×260 для Gabbro.
5. Обновите [`projects.json`](projects.json). Это источник истины для списка
   проектов, версий, платформ, превью, группы сборки, статуса в магазине и PBW.
6. Добавьте или обновите `<project>/CHANGELOG.md`. Для каждой версии исходников
   нужна отдельная верхняя запись `## <version> — YYYY-MM-DD` с конкретными
   пользовательскими изменениями на английском. Старые записи сохраняйте.
7. Выполните `npm run projects:sync`. Не редактируйте вручную сгенерированные
   блоки каталога, списки проектов Makefile, `dist/README*.md` и
   `dist/SHA256SUMS`.
8. Добавьте или обновите тесты и описание выполненной проверки.

Обновление версии не завершено, пока `package.json`, `projects.json` и changelog
проекта не согласованы. `npm run projects:check` проверяет наличие непустой
записи текущей версии. Release notes обновляются автоматически в рамках той же
задачи без отдельного напоминания пользователя. Это правило действует и для
кандидатов и неопубликованных версий; публикация в магазине остаётся отдельным
действием, требующим явного запроса.

## Релизные артефакты

Статус относится к конкретному PBW, а не только к проекту:

- `dist/published/` содержит PBW, чей `versionLabel` совпадает с проверенным
  публичным релизом RePebble; идентичность байтов со скачиванием из магазина
  заявляется только после отдельной проверки;
- `dist/candidates/` содержит устанавливаемые, но публично не подтверждённые
  сборки;
- `dist/experimental/` содержит прототипы с явно описанными ограничениями.

Используйте имя с версией, например `project-name-1.2.3.pbw`. Запишите тот же
путь и версию в `projects.json`, затем запустите `npm run projects:sync`.
Генератор сверит версию `appinfo.json` внутри PBW и обновит SHA-256.

Не помечайте проект опубликованным только из-за готовой формы или PBW. URL и
`publishedVersion` добавляются лишь после появления доступной страницы Appstore
с видимой версией.

## Обязательные проверки

```bash
npm run projects:check
git diff --check
make -n build
make -n standard-apps
```

Для каждого изменённого PBW:

```bash
unzip -t path/to/project-version.pbw
unzip -p path/to/project-version.pbw appinfo.json
```

Запустите тесты и сборку изменённого проекта. Скриншоты эмулятора полезны, но
датчики здоровья, микрофон, телефонные интеграции, wakeup и внешние сервисы могут
требовать физических устройств. Непроверенное покрытие указывайте явно.

Для интерактивного показа и тестирования следуйте
[TESTING.ru.md](TESTING.ru.md): сначала используйте браузерный эмулятор, загрузите
Emery / Pebble Time 2 и установите текущий PBW. Стандартный эмулятор Pebble SDK
используйте только после конкретного сбоя браузерного пути либо если нужное
поведение не поддерживается; причину перехода укажите явно.

## Материалы магазина

Перед публикацией подготовьте требуемые RePebble размеры: нативный скриншот
Emery 200×228, иконки и баннер 720×320, когда он нужен карточке. Храните тексты
листинга, release notes, описание приватности и ссылку на исходники рядом с
проектом.

## Безопасность и приватность

- Не коммитьте credentials, session tokens, приватные URL, `.env`, данные Apple
  Account, Telegram bot tokens и OpenAI credentials.
- В общей документации используйте placeholders.
- Документируйте сетевые адреса, разрешения, хранимые значения, retention и
  зависимости от оборудования или сервисов.
- Reverse-engineered и private API всегда помечайте экспериментальными и явно
  описывайте границы работоспособности и публикации.

## Перед передачей изменений

- Проверьте полный diff и сохраните несвязанные пользовательские изменения.
- Сверьте английскую и русскую документацию.
- Проверьте наличие записи `CHANGELOG.md` для каждой изменённой версии исходников.
- Проверьте локальные ссылки и пути превью.
- Не выполняйте commit, push, публикацию или deployment без явного запроса.
