# Тестирование Pebble-приложений

[English](TESTING.md) · **Русский**

Браузер — основной способ показать циферблат или watchapp для интерактивного
тестирования. Стандартный эмулятор Pebble SDK используется только тогда, когда
браузерный путь недоступен, не устанавливает или не запускает PBW либо не может
воспроизвести проверяемое поведение.

## Основной сценарий: браузер

Используйте [pebble-qemu-wasm](https://github.com/ericmigi/pebble-qemu-wasm),
который запускает настоящую прошивку PebbleOS в QEMU, собранном в WebAssembly.

1. Соберите запрошенный проект или выберите точный артефакт из
   [`projects.json`](projects.json). Если пользователь просит показать текущие
   изменения исходников, нельзя подменять их старым PBW.
2. Откройте [браузерный эмулятор PebbleOS](https://ericmigi.github.io/pebble-qemu-wasm/).
3. Выберите Emery / Pebble Time 2, если доступен выбор платы, нажмите **Boot** и
   дождитесь полной загрузки PebbleOS.
4. Нажмите **Upload .pbw** и выберите локальный бинарник. PBW также можно
   перетащить на экран часов. Публичную ссылку `apps.repebble.com` или прямой URL
   PBW можно вставить в поле установки.
5. Используйте кнопки на экране или клавиатуру:

   | Клавиша | Кнопка Pebble |
   | --- | --- |
   | `↑` | Up |
   | `↓` | Down |
   | `→` или `Enter` | Select |
   | `←`, `Escape` или `Backspace` | Back |

6. Проверьте состояния, относящиеся к запросу. Если пользователь попросил
   показать приложение, оставьте браузер с интерактивным результатом доступным.

Онлайн-эмулятор также позволяет менять заряд, формат 12/24 часа, compass,
shake/tap и отправлять тестовые уведомления. Браузер — основной способ показа и
интерактивной проверки, но не доказательство работы на физических часах.

## Локальный запуск браузерного эмулятора

```bash
git clone https://github.com/ericmigi/pebble-qemu-wasm.git
cd pebble-qemu-wasm
python3 server.py 8080
```

Откройте `http://localhost:8080`. Нужно использовать штатный `server.py`: он
добавляет Cross-Origin-Opener-Policy и Cross-Origin-Embedder-Policy для
`SharedArrayBuffer`. Обычный статический HTTP-сервер для этого не подходит.

## Fallback: стандартный эмулятор Pebble

Переходите к SDK-эмулятору, если не работают загрузка браузерной прошивки,
WebAssembly, загрузка PBW или установка приложения. Он также нужен для логов,
SDK-специфичного поведения, отладки PebbleKit JS и возможностей, которых нет в
браузерном пути.

Установка готового бинарника:

```bash
pebble install --emulator emery --logs path/to/application.pbw
```

Сборка и запуск из каталога проекта:

```bash
pebble build
pebble install --emulator emery --logs
```

Если SDK-эмулятор показывает старое состояние:

```bash
pebble kill
pebble wipe
pebble build
pebble install --emulator emery --logs
```

При fallback укажите, почему браузерный путь не сработал. Ни браузер, ни
SDK-эмулятор не заменяют физические часы при проверке микрофона, Health sensors,
wakeup, телефонных bridges, Bluetooth, внешних сервисов и настоящих credentials.

## Как трактовать запрос пользователя

Если пользователь просит «покажи», «открой», «запусти» приложение или циферблат
для тестирования, это означает:

1. собрать или выбрать нужный PBW;
2. открыть браузерный эмулятор;
3. загрузить и установить PBW;
4. оставить интерактивный результат доступным пользователю.

Стандартный SDK-эмулятор используется только после конкретного сбоя браузерного
пути или когда требуемая проверка не поддерживается браузером.
