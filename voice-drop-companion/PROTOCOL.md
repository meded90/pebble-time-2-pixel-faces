# Voice Drop protocol v1

Pebble Protocol endpoint: `10001`. Все многобайтные поля little-endian.

Команды телефона:

| Код | Имя | Поля после кода |
| ---: | --- | --- |
| `0x01` | `LIST` | `after_recording_id:u32` |
| `0x02` | `FETCH_CHUNK` | `id:u32 chunk:u16 offset:u32` |
| `0x03` | `DATA_ACK` | `id:u32 chunk:u16 next_offset:u32` |
| `0x04` | `RECORDING_ACK` | `id:u32` |

Ответы часов:

| Код | Имя | Назначение |
| ---: | --- | --- |
| `0x81` | `QUEUE_STATUS` | число записей и общий размер |
| `0x82` | `RECORDING_META` | параметры Speex, CRC32, чанки |
| `0x83` | `CHUNK_DATA` | до 220 байт с абсолютным offset |
| `0x84` | `CHUNK_DONE` | подтверждённый размер чанка |
| `0x85` | `RECORDING_DONE` | конец записи или списка (`id=0`) |
| `0xff` | `ERROR` | код ошибки и recording id |

Запись на часах — последовательность `[frame_length:u8][speex_frame]`, разбитая
на PFS-файлы по 16 КБ. Метафайл создаётся последним, поэтому незавершённая запись
никогда не появляется в списке. Часы удаляют метафайл и чанки только после
`RECORDING_ACK`.

Серверный контейнер начинается с `VDROP001`, имеет 40-байтовый заголовок и затем
неизменённый поток кадров. Полная схема проверяется тестами в
`../voice-drop-server/test`.
